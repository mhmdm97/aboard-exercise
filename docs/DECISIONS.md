# Decisions & assumptions

One line per entry, newest at the bottom. Format: `- [area] decision: reason`.

- [stack] .NET 10 minimal API + React 19/TS/Vite monorepo: chosen ahead of time for the exercise.
- [backend] Feature-folder minimal APIs, no extra layered projects: keeps the code small and readable under time pressure.
- [frontend] Vite dev proxy for `/api` → backend:5000 instead of relying on CORS (a CORS policy also exists for direct calls).
- [stack] Removed the .NET boilerplate: the brief requires a Node API (supersedes the .NET entries above).
- [domain] Books, not movies: Open Library serves covers by cover ID (`https://covers.openlibrary.org/b/id/<cover_i>-M.jpg`), so the seeded records get real covers cheaply.
- [repo] npm workspaces: `frontend/`, `backend/`, `shared/`. `shared` (`@library/shared`) holds Zod schemas + inferred DTO types used by both API validation and frontend forms, exported as TS source (Vite/tsx/Vitest compile it; the backend prod build bundles it with tsup).
- [runtime] Node 22 LTS everywhere (Docker, CI), ESM only, TypeScript strict.
- [backend] Fastify 5 + `fastify-type-provider-zod`: schema-validated, typed routes, and the same schemas generate OpenAPI (`@fastify/swagger` + Swagger UI at `/api/docs`).
- [db] PostgreSQL 16 + Drizzle ORM (drizzle-kit migrations). SQL-first and close to the metal, so Postgres features (pg_trgm / full-text search) stay easy to use.
- [auth] Server-side sessions stored in Postgres; opaque random token in an httpOnly, SameSite=Lax cookie (only its SHA-256 hash stored). Passwords hashed with argon2 (`@node-rs/argon2`, prebuilt, no node-gyp). Chosen over JWT-in-localStorage: real logout/revocation, no token readable by JS.
- [roles] `admin`: full CRUD on books (and lookups). `member`: browse/search/filter + personal favourites. Self-registration always creates `member`; admins come from the seed.
- [tests] Vitest in all workspaces. Backend integration tests use `app.inject()` against a real Postgres test DB (`DATABASE_URL` of a test database); CI uses a Postgres service container. Frontend: Vitest + React Testing Library.
- [frontend] react-router + TanStack Query for server state; react-hook-form + zodResolver with the shared schemas; plain CSS modules, mobile-first.
- [versions] fastify 5.12, zod 4.6 (fastify-type-provider-zod 7 supports zod >=4.1.5), drizzle-orm 0.45, vitest 5, tsup 8; frontend dependency majors unchanged.
- [backend] Backend tests live next to the code as `<feature>.test.ts`; `buildApp({ env, db })` takes its dependencies so tests use `app.inject()`.
- [backend] Helmet CSP is disabled outside production so Swagger UI works; ESLint for backend+shared lives in the root `eslint.config.js` (frontend keeps its own).
- [ci] Single CI job on Node 22 with a `postgres:16` service (`library_test`); `.gitignore` allows `.env.*.example` files.
- [db] Migrations: `0000_pg_trgm` (custom: `CREATE EXTENSION pg_trgm`) runs before `0001_schema` so the trigram GIN indexes (books.title, authors.name) can be created; `averageRating` is `numeric(3,2)` mapped to a JS number.
- [seed] `backend/src/db/seed/books.json` (383 books, 21 genres) is real Open Library data, generated by `backend/scripts/fetch-seed-books.ts` and committed; the first hand-written version had ISBNs that did not match real editions. Pre-1 AD works would have `publishedYear = null`.
- [seed] `average_rating` is the Open Library community average when `ratings_count >= 5`, otherwise a deterministic synthetic value (2.50-5.00 from SHA-256 of the ISBN). Seed logic is `src/db/seed-library.ts` (`seedLibrary(db)`, idempotent, one transaction, keyed on ISBN; it also stores `subtitle`); `seed.ts` is the CLI entry (also built to `dist/db/seed.js`, JSON bundled by tsup).
- [seed] Fetch approach: Open Library Search API per subject (sort by reading log, English, 100 results) plus an explicit must-have list (`title` + `author` search), merged before round-robin balancing (16 primary picks per genre, so every genre has 17+ books); descriptions come from `/works/<id>.json` (markdown, footnotes and source trailers stripped, at most 3 sentences / 400 chars); `coverUrl` uses the search `cover_i`; ISBN is the first unused valid ISBN-13 (ISBN-10 converted) of the work. Requests are limited to 1 per second with retries, and responses are cached (git-ignored) in `backend/.cache/openlibrary/`. A genre besides the queried one needs 3 subject matches; max 3 per book. Re-seeding an existing DB adds new books and does not remove old ones (use `docker compose down -v` for a clean DB). Must-have titles carry explicit genres; religious scripture, textbooks, compilations, accented (translated) titles and graphic-novel adaptations are filtered out. A book keeps the queried genre only if its own subjects support it (2+ matches or one among its first 10 subjects); non-fiction genres are never given to books with a fiction or novel subject; otherwise the book is skipped and the next candidate is used. A small `GENRE_OVERRIDES` map (keyed by work key) hand-sets genres for the remaining clear mismatches.
- [tests] Backend Vitest uses a `globalSetup` that migrates the test DB; test files run serially (`fileParallelism: false`) since they share one DB; use `createTestDb()`/`truncateAll()` from `src/test/db.ts`. Shared schema tests live in `shared/` (vitest added).
- [shared] `bookInputSchema` normalises (trims, strips ISBN hyphens, blank optionals become null, `genreSlugs` defaults to `[]`); `bookListQuerySchema.genre` accepts repeated or comma-separated values.
- [frontend] Router: react-router 8 data router (`createBrowserRouter`, routes in `src/routes.tsx`); TanStack Query defaults staleTime 30s, no retry on 4xx; devtools in dev only. Vitest + RTL + jsdom for frontend tests.
- [auth] Sessions: 32-byte base64url token, 7-day TTL (`SESSION_TTL_DAYS`), cookie `sid` unsigned (token is opaque random); expired sessions deleted lazily. Login verifies against a dummy argon2 hash for unknown emails (no timing leak); register/login rate-limited 10/min/IP (off in tests).
- [auth] CSRF: SameSite=Lax cookie + JSON-only bodies (Fastify has no form-urlencoded parser, so those get 415); no CSRF tokens.
- [seed] Demo users `admin@library.local` / `Admin123!` (admin, "Ada Admin") and `member@library.local` / `Member123!` (member, "Max Member"): committed on purpose for the README; `db:seed` re-resets them.
- [search] `q` matches title/subtitle/author via `ILIKE '%q%'` (LIKE wildcards escaped) OR pg_trgm `q <% title|author.name` (typo tolerant; the index-supported operator form so the GIN trigram indexes are usable). Its threshold is the GUC `pg_trgm.word_similarity_threshold`, set to 0.4 with a transaction-local `set_config` inside `listBooks`' transaction. Relevance ordering still uses the `word_similarity()` function. `sort` is optional in `bookListQuerySchema`: with `q` and no `sort` results are ordered by relevance (best similarity, substring-in-title boosted), with no `q` and no `sort` by title; an explicit `sort` always wins. NULLs always sort last; `id` is the final tiebreaker.
- [api] `GET /api/authors?q=&limit=` is a plain substring ILIKE (default limit 20, max 50) ordered by name; `GET /api/genres` returns all genres by name (no bookCount). Genre/author lookups live in `features/lookups/`.
- [api] Book writes (`POST/PUT/DELETE /api/books`, admin) run in one transaction; PUT is a full replace; authors are matched case-insensitively by name, else created; unknown genre slug -> 400 `VALIDATION_ERROR` (`details.genreSlugs`), duplicate ISBN -> 409 `CONFLICT`.
- [api] Favourites (`PUT/DELETE /api/books/:id/favourite`, `GET /api/me/favourites[/ids]`) are idempotent; the PUT returns 404 for an unknown book, DELETE is 204 regardless.
- [frontend] Library filters live in URL search params (replace history); paging is not in the URL (infinite scroll restarts at page 1 on any filter change). Year inputs commit on blur/Enter; search is debounced 300 ms. `sort` is omitted from requests until the user picks one so the server can rank by relevance. Open Library cover URLs get `?default=false` and fall back to a generated cover on error. "Clear filters" also clears the search text.
- [frontend] Auth state lives only in the TanStack Query cache (`["auth","me"]`; `GET /api/auth/me` answers 200 `{ user: UserDto | null }`, so anonymous page loads log no failed request); no React context. Forms use react-hook-form + zodResolver with the shared schemas. `?redirect=` accepts only paths starting with a single `/`.
- [frontend] Book detail author names link to `/?author=<id>` and genre chips to `/?genre=<slug>`; the Library shows an "Author: <name>" chip (name resolved from the loaded books, `…` until then) that removes the filter.
- [frontend] Delete success navigates to `/` with router state `{ message }`, announced in a polite `role="status"` region on the Library page.
- [frontend] Book form: `authorNames` is a plain `string[]` in the schema, which `useFieldArray` cannot hold, so the author list is controlled via `useWatch`/`setValue` (add/remove, 1..10) with a native `<datalist>` fed by `GET /api/authors?q=&limit=8` (250 ms debounce). Blank number inputs and blank cover URL map to null; a 409 on save is shown as the ISBN field error, other API errors as a banner; save navigates (replace) to the book detail.
- `COOKIE_SECURE` env (optional; defaults to true when NODE_ENV=production) controls the `sid` cookie `secure` flag; compose sets it false because the stack is served over plain http on localhost.
- Docker images use `node:22-slim` (glibc, safe for `@node-rs/argon2` prebuilds) and `nginx:alpine`; the backend entrypoint migrates, seeds when `SEED_ON_START=true` (idempotent), then starts. Verified end to end with `docker compose up` (images built, all services healthy, migrations + seed on start and on restart, SPA fallback and /api proxy through nginx, login, Swagger, backend runs as non-root `node`). Sizes: backend ~408MB (89MB compressed), frontend ~94MB (26MB compressed).
- A11y: `useDocumentTitle` sets "<page> · Shelf" per route; book cards use `h2` (page `h1` > card `h2`); fallback cover lightness lowered to 26% so white text meets WCAG AA for every hue; `/api/health` uses `logLevel: 'warn'` so the Docker healthcheck does not flood request logs.
- Frontend: non-landing routes are code-split via react-router route `lazy` (HydrateFallback = Spinner); Query devtools are only imported when `import.meta.env.DEV`; first 8 covers load eagerly (first 4 fetchpriority=high), the rest lazy; `vite preview` proxies `/api` like dev.
- [design] UI/motion redesign spec ("Shelf", Fraunces + Instrument Sans, paper/oxblood light + ink/rose dark, generated cloth covers, motion table with reduced-motion alternatives, all screens at 1280/390): https://claude.ai/artifact/TE393h4tJbn4e1BQ56wQYN (private Claude Design canvas; ask the owner for access). Not implemented yet.
- [design] Fonts are self-hosted via `@fontsource-variable/fraunces` (`opsz.css`, weight + optical size axes) and `@fontsource-variable/instrument-sans` (`wght.css`), imported in `main.tsx`; Google Fonts is not used because the nginx CSP is `font-src 'self'` (and `style-src 'self' 'unsafe-inline'`) and must not be loosened. Font families are `'Fraunces Variable'` / `'Instrument Sans Variable'` with Georgia / system-ui fallbacks.
- [design] Tokens live in `frontend/src/index.css` (light default, dark via `prefers-color-scheme`, no theme toggle). The old names (`--color-*`, `--space-*`, `--radius-*`, `--font-*`) stay as aliases onto the new tokens so un-restyled pages keep working; new code uses `--bg/--surface/--ink/--accent/...`, `--sp-*`, `--r-*`, `--dur-*`, `--ease-*`. Shared primitives are global classes in `components/ui/ui.css` (`.btn` + `-primary|-secondary|-ghost|-danger|-danger-outline|-icon`, `.btn-link`, `.chip` (+`.on`, `.chip-filter`), `.badge`, `.tag`, `.input`/`.select`, `.field-label`, `.visually-hidden`); `.button` is kept as an alias of the primary button.
- [design] Motion is CSS only (no animation library): keyframes live next to the component that uses them (CSS modules scope keyframe names, so shared ones are not global). Grid entrance is scroll-triggered (not on mount, since infinite scroll mounts the next page ahead of the viewport): `hooks/useRevealOnScroll` keeps ONE IntersectionObserver (threshold 0.15, rootMargin `0px 0px -10% 0px`) and sets `data-revealed` + `--i` directly on the card DOM node the first time it is visible, then unobserves it (never replays on re-render/scroll back; new filter results are new nodes and animate). `--i` is the card's DOM order within the observer callback batch, capped at 7, so each screenful cascades from its own first card. Unrevealed cards sit at opacity 0 / translateY(18px) / scale(.97). First row (index < 4, the `fetchpriority=high` LCP covers, `data-eager`) never gets opacity 0 (it only rises) so LCP is not delayed by a fade (Chrome ignores opacity-0 elements as LCP candidates). `focusin` on a card reveals it immediately; no IntersectionObserver reveals at once; reduced motion has no hidden state at all. Timing (user found the first pass too quick): reveal 560ms, stagger 65ms, hover lift 280ms, heart pop/burst 500ms, chips 250ms in/out, drawer 350ms in / 250ms out, dialog 250ms in / 180ms out, toast 350ms in / 250ms out, route cross-fade 180ms out + 300ms in, cover morph 500ms (tokens `--dur-*` in index.css; the JS exit timers in ActiveFilters/FilterDrawer/Toast/ConfirmDialog mirror them). The heart pop/burst runs only after a user press (not for hearts that are already on at load). Filter chips: scale-in on add; removed chips stay in the DOM (derived during render) for 140ms with a width-collapsing fade so neighbours slide closed (no View Transitions yet, that is part 2). Skeletons only become visible after 150ms (CSS animation delay). Every animation has the reduced-motion alternative from the spec table (opacity-only or instant; static skeleton/spinner; no tilt).
- [design] The mobile filter drawer renders in a portal on `document.body` only while open; the app root (`#root`) is made `inert` and body scroll is locked while it is open, Escape / backdrop / close button / "Show n books" dismiss it (220ms exit animation), focus moves to its heading on open and back to the trigger on close, and it closes if the viewport grows past 768px. The desktop sidebar and the drawer render the same `FilterFields`; the sidebar is `display: none` below 768px. Filters apply live (URL state, as before); "Show n books" only closes.
- [design] Library page extras beyond the old behaviour: every active filter (genre, author, years, min rating, sort) is a removable chip (the sort chip exists because `countActiveFilters` counts sort); the genre filter is a row of `aria-pressed` buttons and min rating a 5-way radio control (was checkbox list and select); `/` focuses the search box.
- [design] Generated covers: palette of 12 cloth colours indexed by djb2(title) % 12 (`features/books/coverStyle.ts`, same as the mockup), `role="img"` with `aria-label="Cover of <title>"`; real images keep the same 2:3 box and the old `onError` / `naturalWidth <= 1` fallback. White (and the 92% white author line) on every palette colour is >= 6.7:1, enforced by a unit test.
- [design] View Transitions (react-router 8, `react-router/dom` RouterProvider is required for `useViewTransitionState`): links/navigations pass `viewTransition={canViewTransition()}` (`hooks/viewTransition.ts`), which is false when `document.startViewTransition` is missing (Firefox < 144: plain instant navigation, `.page-in` fade is the fallback) or `prefers-reduced-motion` is set (no transition at all, plus CSS `animation: none` on the pseudo-elements). Root cross-fade uses the tokens (old `--dur-fast`, new `--dur-base` +60ms). Cover morph: a `Cover morph` only gets `view-transition-name: cover-<id>` while `useViewTransitionState('/books/<id>')` is true, so exactly one cover carries a name. The detail page uses cached list data as placeholder (`useBook(id, {showCachedFirst})`) so the cover exists in the first frame of the transition. The in-page "Back to library" runs its own `startViewTransition` around `navigate(-1)` (RR's navigate(-1) takes no options); the browser back/forward buttons DO animate without extra code (see the polish entry below; this sentence used to say they did not). `<ScrollRestoration/>` added to Layout.
- [design] Deviations from the mockups: form labels keep "Published year"/"Create book"/"Add author" (tests, nav already has "Add book"); genres limit stays 10 (hint "Choose up to 10"); author autocomplete stays a native `<datalist>`; the favourite button's visible text swaps ("Add to favourites"/"In your favourites") while its accessible name stays "Favourite <title>" with aria-pressed; success message does not move focus to the result count. Form validation shows a summary banner whose links focus the invalid fields.
- [dev] Vite's string proxy target implies `changeOrigin: true`, which made the backend see Host `localhost:5000` against Origin `localhost:5173` and the CSRF Origin check return 403 on login. Fixed in `vite.config.ts` with `{ target, changeOrigin: false }` for dev and preview; verified with a Playwright login through the dev server, no Origin rewriting needed.
- [csp] Zod's JIT probe (`new Function('')`) tripped the nginx CSP (`script-src` without `unsafe-eval`) as a reported violation on every page; fixed by `z.config({ jitless: true })` in `frontend/src/zodConfig.ts` (first import of `main.tsx`; `zod` added as a direct frontend dependency for that). No other violations on `/`, a book page or `/login`.
- [ui] Generated cover colour hashes title + first author (plus a final bit-mix, since plain djb2 % 12 bunched sequential titles); the detail-page favourite button's accessible name is its visible text (WCAG 2.5.3), the card heart keeps `aria-label`.
- [design] Theme toggle: `data-theme="light"|"dark"` on `<html>` overrides the OS; no attribute = follow the system. Dark tokens live in `index.css` twice (`:root[data-theme="dark"]` and `@media (prefers-color-scheme: dark) { :root:not([data-theme="light"]) }`) because CSS cannot share a declaration block between a media query and a selector. `ThemeToggle` in the header is one button cycling System, Light, Dark (icon = current state, aria-label "Theme: Light. Switch to Dark"); the choice is kept in `localStorage['shelf-theme']` (removed for System; every access in try/catch). No flash on load: `public/theme-init.js` is a synchronous classic script in `<head>` (allowed by the nginx CSP `script-src 'self'`, no inline script) that sets `data-theme` before first paint; its key and colours must stay in sync with `hooks/useTheme.ts`. A `<meta name="theme-color">` was added (it did not exist) and is updated by both.
- [design] Browser back/forward animation needs no code: React Router 8 records every pair of paths navigated with `viewTransition` (persisted in sessionStorage) and, on a POP between such paths, runs `document.startViewTransition` itself with swapped current/next locations, so `useViewTransitionState` names the right cover. Verified in Chromium: back from a detail page cross-fades and morphs the cover into its card, only one `cover-<id>` name exists at a time, scroll is restored to the card's position, forward replays it, reduced motion makes no transition, and browsers without the API navigate instantly. No popstate/Navigation API hook was added. Not animated: back to a page reached without a transitioned navigation (e.g. a deep link or reload followed by Back where no pair was recorded).
- [design] Empty states: `ShelfMark` (inline SVG bookshelf, token colours, `aria-hidden`) is the mark for "No books match your filters" and the empty Favourites page (with a dashed heart in the gap). Entrance: books rise/fade in with a small stagger; no animation under reduced motion.
- [e2e] Playwright suite in the `@library/e2e` workspace (`e2e/`), run by `npm run test:e2e`. Its script is named `test:e2e` (not `test`) so the root `npm test` (`--workspaces`) never starts it. It serves the built backend (`node backend/dist/server.js`) and `vite preview` on ports 5100/5174, uses a dedicated `library_e2e` DB, and workers=1 since specs share it. Playwright starts `webServer`s before `globalSetup`, so DB creation/migrate/seed (`e2e/setup-db.ts`, via tsx) is chained before the backend in its webServer command. `frontend/vite.config.ts` reads `API_PROXY_TARGET` (default `http://localhost:5000`) so the proxy follows the e2e backend port. Covers from openlibrary/archive.org are routed to 404. Mutating specs use unique titles and clean up in `finally`. CI: separate `e2e` job on the same Postgres service image; `library` is the superuser so it can `CREATE DATABASE`.
